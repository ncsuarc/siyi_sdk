How to measure and interpret delay

Browser and server timings follow the named command. SDK send measures local dispatch, not camera execution. Center waits for a reply; recording first reads the current state. Mode and recording confirmation happens in the background and is measured separately. Camera RTT uses status readbacks with no retries and a 700 ms timeout; it includes camera processing. Percentiles exclude failed queries. Frame age is time since the server received a decoded frame, not video delay.

To measure visible delay, film your hand pressing a control and the live view together, then count frames until motion appears. Delay in milliseconds = frames × 1000 ÷ filming FPS. Compare command timings with Live View on and off to isolate video overhead.
